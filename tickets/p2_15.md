# P2-15 — FE Monitoring per-platform

> Phase: **P2 — Scrape (IG + Threads) & Monitoring** · Priority: **P1** · Estimate: **L** · Depends on: P2-14, P1-17

## Context

Fase data: scrape via Apify actor (K8s Job ephemeral), ingest raw → MinIO → Postgres, metric time-series, alert. **Plus monitoring akun resmi (Official Accounts)** yang read-only: metrik dari 3rd-party provider, terpisah dari jalur worker/scrape.

Tiket ini: FE Monitoring per-platform.

## Scope

Halaman Overview + 7 halaman per platform (KPI strip, tren, tabel, freshness badge `stale`)

## Technical Notes

Port 1:1 dari prototype `docs/prototype/monitoring.html` + `analytics-*.html` (sudah disetujui). Nav group 'Monitoring' (Overview + 7 platform). Layout contract tetap; jangan ada `mt-*` di section top-level. Badge `stale` bila freshness > 60 menit; tombol Refresh memicu `POST /analytics/refresh`. Semua platform dirender walau datanya kosong (state empty yang jelas).

Rate limit dipaksa scheduler BE, bukan di dalam job. Raw payload di MinIO, normalisasi idempotent (upsert by externalId). TimescaleDB untuk MetricSnapshot. **OfficialAccount ≠ Account** (worker): akun resmi tanpa kredensial/login/action, hanya subjek analitik. Provider diakses lewat interface `Provider` (provider-agnostic) — jangan hardcode vendor. Ingest gagal tidak boleh memblokir jalur action/scrape; tampilkan snapshot terakhir + badge `stale`.
