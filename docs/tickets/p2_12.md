# P2-12 — Analytics ingestor

> Phase: **P2 — Scrape (IG + Threads) & Monitoring** · Priority: **P0** · Estimate: **L** · Depends on: P2-11

## Context

Fase data: scrape via Apify actor (K8s Job ephemeral), ingest raw → MinIO → Postgres, metric time-series, alert. **Plus monitoring akun resmi (Official Accounts)** yang read-only: metrik dari 3rd-party provider, terpisah dari jalur worker/scrape.

Tiket ini: Analytics ingestor.

## Scope

Cron 30 menit + on-demand; normalisasi → `AnalyticsSnapshot`/`AnalyticsMention`; update `lastFetchedAt`; tulis `AnalyticsIngestRun`

## Technical Notes

Idempotent: satu snapshot per `(officialAccountId, ts)` (bucket 30 menit). Tulis `AnalyticsIngestRun` `PENDING→RUNNING→SUCCESS|PARTIAL|FAILED` dengan `accountsOk`/`accountsErr`. Retry + timeout HTTP; gagal berulang → alert (F5.8). Emit SSE `analytics-updated`. Provider down ≠ error page: data terakhir tetap tampil.

Rate limit dipaksa scheduler BE, bukan di dalam job. Raw payload di MinIO, normalisasi idempotent (upsert by externalId). TimescaleDB untuk MetricSnapshot. **OfficialAccount ≠ Account** (worker): akun resmi tanpa kredensial/login/action, hanya subjek analitik. Provider diakses lewat interface `Provider` (provider-agnostic) — jangan hardcode vendor. Ingest gagal tidak boleh memblokir jalur action/scrape; tampilkan snapshot terakhir + badge `stale`.

## Acceptance Criteria

- [ ] Snapshot idempotent per `(account, ts)`
- [ ] `IngestRun` SUCCESS/PARTIAL/FAILED tercatat

## Test Plan

Integration mock actor; unit normalizer per platform; re-run ingest tidak duplikat. Unit provider adapter pakai fake HTTP server; unit ingestor: idempotent per (account, ts), `IngestRun` transisi status, provider error → PARTIAL/FAILED.
