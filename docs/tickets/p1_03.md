# P1-03 — K8s provisioner

> Phase: **P1 — Account Lifecycle & Provisioning** · Priority: **P0** · Estimate: **L** · Depends on: P1-02

## Context

Fase inti operasional: operator menambah akun dari UI → BE provisioning container → worker login headful interaktif → session tersimpan. Tanpa akun aktif, tidak ada scrape/action.

Tiket ini: K8s provisioner.

## Scope

`internal/adapter/k8s` create/delete pod+PVC+service; rate limit 10 create/menit

## Technical Notes

Provisioner **dual-mode**: `PROVISIONER_MODE=k8s` (prod) vs `static` (lokal — daftar worker dari baris `Worker` hasil seed, tak memanggil K8s API). Logika tetap 1 port `K8sClient`/`Provisioner` interface; adapter `static` = no-op. envtest hanya jalan bila Docker/K8s tersedia.

Invarian kunci: 1 container = 1 device = N akun, maks 1 per platform (@@unique([workerId, platform])). Channel: queue:action:<workerId> + control-<workerId>. Commit DB SEBELUM publish/enqueue.
