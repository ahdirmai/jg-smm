# P1-05 — Assign akun (bin-packing)

> Phase: **P1 — Account Lifecycle & Provisioning** · Priority: **P0** · Estimate: **M** · Depends on: P1-04

## Context

Fase inti operasional: operator menambah akun dari UI → BE provisioning container → worker login headful interaktif → session tersimpan. Tanpa akun aktif, tidak ada scrape/action.

Tiket ini: Assign akun (bin-packing).

## Scope

Cari container slot platform kosong; fallback auto-create (`PROVISION_AUTO_CREATE`); `MAX_ACCOUNTS_PER_CONTAINER`

## Technical Notes

Assign akun pakai bin-packing, **bukan** auto-create buta. Fleet default kosong; container dibuat manual (P1-19). Auto-create = fallback saat tak ada slot (`PROVISION_AUTO_CREATE=true`, default). Auto-delete HANYA untuk container `source=AUTO`; `source=MANUAL` bertahan sampai user Remove.

Invarian kunci: 1 container = 1 device = N akun, maks 1 per platform (@@unique([workerId, platform])). Channel: queue:action:<workerId> + control-<workerId>. Commit DB SEBELUM publish/enqueue.

## Acceptance Criteria

- [ ] Add akun → ter-pack
- [ ] tak ada slot → auto-create atau `NO_SLOT`
- [ ] container `AUTO` 0 akun → auto-delete, `MANUAL` bertahan
