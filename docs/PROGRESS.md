### P3-01 notes

- Claim is `FOR UPDATE SKIP LOCKED` per account, never global; `attempts` is bumped at claim time and the worker is stamped then (not at enqueue), because a job goes to whichever worker owns the account's queue.
- `ActionLog` is the source of truth for a verdict; `action_job.status` is only the projection the queue list reads. Nothing is inferred from the absence of a log row — there is no SUCCESS without verification (P3-08).
- The upsert's COALESCE protects an earlier screenshot/excerpt: a terminal callback that omits them never erases what the RUNNING callback captured. `rendered_text` is always authoritative (the commanded input).
- A retry is always a NEW attempt number: the previous attempt's verdict survives untouched, and `ListActionLogsByJob` is newest-first.

### P3-02 notes

- Dedupe (7 days per target) is a QUERY, not a constraint: `PickForTarget` excludes any template whose `action_log` rows touch this target inside 7 days. It is a pool property (which variants are still fresh), not a row property, and a CHECK cannot express a temporal join.
- Weighted random lives in the service, not SQL: the store returns the eligible candidate set heaviest-first, the service draws with probability proportional to weight. Needs no SQL seed and is testable with an injected `*rand.Rand` (4000 draws, weight 3:1 lands in 3000±300).
- `vars` is the DECLARED set (ERD), not parsed out of the text: `Validate()` requires every `{var}` in the text to be declared and every declared var to be used, so the composer catches a typo before a worker can post a raw `{placeholder}`. `Render()` leaves an unresolved placeholder in place on purpose and `Pick()` rejects the result with `ErrValidation` — a worker must never post `"{topic}"`.
- Empty pool is `ErrTemplatePoolEmpty`, not a fallback to a repeated variant: repeating a comment on one target is what dedupe exists to prevent, so the honest action is to skip.
- `ScreenBanned` (denylist screen) ships on the service for P3-03 to wrap into the screening pipeline; the per-template denylist column belongs to the pool here.
